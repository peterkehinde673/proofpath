ProofPath · developer reference

How one evidence set becomes a report

ProofPath keeps a small evidence set in the browser for review, sends readable files to the local Node endpoint for AI analysis, validates source links, then renders the timeline and report from the same result.

One action through the app

Reference route through the source

Reference route · not toured interactively
01 · Browser input

public/app.js · acceptSelectedFiles()

Checks type and size, reads supported files, keeps them in browser memory, and renders the review list with remove actions.

02 · Server analysis

server.mjs · handleAnalyze()

prepareFiles() checks limits and signatures; callGemini() requests a focused response; validateAnalysis() rejects unsupported citations and status combinations.

03 · Visible result

public/app.js · renderAnalysis() / renderReport()

The timeline maps cited file IDs to selected filenames. The report uses that same validated analysis; it makes no second AI request.

A practice to reuse

Turn an important trust rule into an observable acceptance criterion before coding. Here, “Supported needs direct source evidence” is enforced by validateAnalysis() and the tests that accept a linked event and reject one without evidence. That pairing catches an unsafe result shape before it reaches the screen.
